# 功能 / 零件 / 感測規格

這份表是從**軟體原型反推出來的硬體需求**，不是選型結論。SIM 產生訊號用的振幅與雜訊、ING 濾波與門檻用的頻帶、PAM 拒絕動作用的極限，都是程式裡實際跑的數字；硬體那一側目前沒有任何東西被驗證過。

每一列都標了來源，因為這兩種數字的可信度差很多：

| 標記 | 意思 |
|---|---|
| 【碼】 | 程式裡實際存在並被測試涵蓋的數值，改它會改變結果 |
| 【PRD】 | PRD 指定，程式遵守 |
| 【推】 | 由【碼】的數值推導出的硬體需求（例如「底噪要小於事件振幅的 1/10」） |
| 【擬】 | 候選提案，尚未選型、尚未詢價、尚未量測 |
| 【待】 | 需要先做實驗或詢價才能填 |

## 2. 感測通道規格

| 通道 | 量測什麼 | 取樣率 | 有效頻帶 | 滿刻度 / LSB | 底噪要求 | 事件訊號量 | 偵測角色 |
|---|---|---|---|---|---|---|---|
| **聲學** | 頸部表面吞嚥聲 | 16 kHz【碼】 | 300–3000 Hz【碼】 | ±1.0 正規化聲壓 / 3.1e-5【碼】 | ≤ 0.004 rms【推】 | 0.09（約 27 dB SNR）【碼】 | 權重 0.40，robust z ≥ 5.0（鼾聲段 7.5） |
| **鼾聲**（同一支麥克風） | 上呼吸道振動 | 16 kHz【碼】 | 60–300 Hz【碼】 | 同上 | 同上 | — | 不參與投票；只做軟旗標與門檻提高 |
| **IMU 加速度** | 舌骨／喉部上抬位移 | 100 Hz【碼】 | 20 Hz 低通（動態）、0.3 Hz 低通（重力）【碼】 | ±4 g / 125 µg【碼】 | ≤ 0.004 g【推】 | 0.055 g（約 23 dB SNR）【碼】 | 權重 0.30，與雙相模板 NCC ≥ 0.50 |
| **IMU 陀螺** | 姿勢轉換 | 100 Hz【碼】 | — | ±500 °/s / 0.0156 °/s【碼】 | 【待】 | — | 目前只用於體動閘控輔助 |
| **呼吸代用訊號** | 由 IMU A-P 軸推得的胸腹起伏 | 100 Hz【碼】 | 0.10–0.60 Hz，**整夜零相位**【碼】 | 同加速度 | 同上 | 0.018 g【碼】 | 不投票；決定吞嚥前後的呼吸相位 |
| **sEMG** | 舌骨上肌群活動 | 2 kHz【碼】 | 20–450 Hz + 50 Hz 陷波【碼】 | ±400 µV / 0.0125 µV【碼】 | ≤ 5 µV rms【推】 | 70 µV（約 23 dB SNR）【碼】 | 權重 0.30，robust z ≥ 4.0 且持續 > 150 ms |
| **導聯脫落** | 電極接觸狀態 | 每 chunk 一次【碼】 | — | 布林 | — | — | 硬閘；同時餵 `electrode_ok` 遙測 |

三個 SNR 落在同一個量級（約 23–27 dB），這不是巧合：**底噪必須比事件振幅小一個數量級**，否則 stage 3 的 robust z 門檻沒有意義。這是選任何一顆感測器時最先要驗的一件事。

**呼吸為什麼不在裝置端濾波**：因果式 0.1–0.6 Hz Butterworth 在正常呼吸速率下有約 0.95 秒的群延遲，接近四分之一個呼吸週期。用它量出來的協調型態準確率只有 0.31–0.62（亂猜是 0.25）。改成整夜零相位一次處理後升到 0.62–0.77。所以裝置端存的是原始軸，不是濾過的。【碼】

## 3. 訊號鏈與資料量

| 階段 | 內容 | 速率 | 一夜（8 小時） |
|---|---|---|---|
| 裝置端原始 | 8 通道 int16 | 37.2 kB/s = 298 kbps【推】 | 1.07 GB |
| MQTT 傳輸 | 上面再 base64（×4/3） | 397 kbps【推】 | 1.43 GB |
| 一個 chunk | 5 秒【碼】 | 186 kB（原始）／248 kB（base64） | 5,760 個 chunk |
| 服務端衍生序列 | 9 條 float32 @ 100 Hz【碼】 | 3.6 kB/s | 104 MB |
| 資料庫 | 每秒一列訊號摘要（Timescale） | — | 28,800 列 |

原始波形保留是 opt-in（`STORE_RAW`，預設關）且有期限（`RAW_RETENTION_DAYS`，預設 90）。**平常存的是那 104 MB，不是那 1.07 GB。**【碼】

上行 298 kbps 是選連線方式的關鍵數字：BLE 5.0 2M PHY 實測應用層吞吐約 0.7–1 Mbps，理論上塞得下，但要連續 8 小時且不能掉封包，功耗與穩定度都吃緊。【擬】v1 走床邊 gateway（Wi-Fi 或有線）比較保險，這也是程式目前假設的架構（MQTT over TCP）。

## 4. 零件表

成本結構分成兩塊，因為它們的採購邏輯完全不同：一塊攤提、一塊每晚都要算。

### 4.1 可重複使用（一次性投資，攤提）

| 零件 | 需求 | 候選規格 | 來源 |
|---|---|---|---|
| 接觸式拾音頭 | 300–3000 Hz 平坦、皮膚耦合、抗環境噪音 | 壓電接觸式麥克風，或骨導型 MEMS 拾音頭 | 【擬】 |
| 6 軸 IMU | ODR ≥ 100 Hz（建議 ≥ 208 Hz 再降取樣）、±4 g / ±500 dps、加速度雜訊密度 ≤ 100 µg/√Hz | 消費級 6 軸 IMU（LSM6DSx / BMI270 / ICM-426xx 這一類） | 【擬】 |
| sEMG 類比前端 | 2 kSPS、20–450 Hz、輸入參考雜訊 ≤ 2 µV rms、**內建導聯脫落偵測** | 生理訊號專用 24-bit ΔΣ AFE（ADS129x 這一類） | 【擬】 |
| MCU | 同時吃 16 kHz 音訊 + 2 kHz SPI + 100 Hz I²C，做 base64 與 MQTT，上行 ~300 kbps；有 FPU | nRF53 / ESP32-S3 / STM32U5 這一類 | 【擬】 |
| 本地儲存 | 斷線緩衝。存原始需 ≥ 2 GB／夜；只存衍生序列則 128 MB 足夠 | microSD 或 eMMC | 【擬】 |
| 連線 | 見 §3。v1 建議床邊 gateway | Wi-Fi gateway 或有線 | 【擬】 |
| 電池 | 連續 8 小時 + 開機餘裕 | 需先量 AFE + MCU + radio 的實際耗流 | 【待】 |
| 外殼／貼附載具 | 頸部曲面貼合、可清消、不壓迫 | — | 【待】 |
| 儲存主機 | PostgreSQL/TimescaleDB + MinIO + Redis + MQTT broker | docker compose 已定義 | 【碼】 |
| 床墊致動 | 見 §5 | 自製或整合現成床（OQ-2 未決） | 【待】 |

### 4.2 每晚消耗（真正決定單次成本）

| 項目 | 為什麼是消耗品 | 來源 |
|---|---|---|
| Ag/AgCl 水膠電極（sEMG 兩片 + 參考一片） | 水膠乾掉後阻抗上升，直接反映在 `electrode_ok` 與 sEMG 底噪 | 【擬】 |
| 醫療級壓敏膠帶／敷料 | 固定拾音頭與 IMU；黏著力是整晚訊號品質的前提 | 【擬】 |
| 皮膚保護膜（barrier film） | 高齡者皮膚脆弱，連續多夜貼附必須先隔離 | 【擬】 |
| 一次性連接線／導聯 | 若採可拋設計；也可改成可清消的重複使用線 | 【擬】 |
| 清潔／去角質棉片 | 貼附前的皮膚準備，直接影響電極阻抗 | 【擬】 |

單價全部【待】詢價。但這張表的形狀本身就是結論：**能不能做，取決於重複使用那一欄；能不能推得動，取決於每晚消耗那一欄。**

## 5. PAM 安全包絡

不是建議值，是程式裡會直接拒絕動作的硬限制，每一次拒絕都帶規則編號寫進稽核紀錄。【碼】【PRD】

| 規則 | 限制 | 值 |
|---|---|---|
| PAM-S1 | 床頭角度範圍 | 0–45° |
| PAM-S1 | 側傾角度範圍 | ±30° |
| PAM-S2 | 最大變化率（慢到不會驚醒或嚇到人） | 2 °/s |
| PAM-S4 | 動作前預告時間 | 30 秒 |
| PAM-S5 | 緊急平躺，位階高於一切（含預告與間隔） | 6 °/s |
| PAM-S6 | 兩次動作最短間隔 | 20 分鐘 |
| PAM-S7 | 所有動作與拒絕寫入不可竄改紀錄 | 雜湊鏈 |
| PAM-S8 | 與分析服務斷線 → 保持位置、停止排程 | — |
| — | 床上沒有人 → 拒絕任何動作 | — |
| — | 沒有人按確認 → 不動 | 無 autonomous 模式 |

排程翻身預設 120 分鐘一次，下限由 PAM-S6 決定（不得低於 20 分鐘）。
